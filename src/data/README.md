# `src/data/`

> **Purpose:** Unify host/device storage and provide VTU, DAT, and level-set input data facilities.

## Core Contents

| File | Responsibility |
| --- | --- |
| `ContainerObject.h` | Track ownership of user-constructible objects by a container |
| `DeviceLayout.h` | Define `deviceField`, `deviceLayout`, and layout composition |
| `HostAoSDeviceSoA.h` | Implement `hostAoSDeviceSoA<HostObject, Layout>` and device field arrays |
| `CudaTypes.h` | Provide `int3` and related types for CUDA and non-CUDA builds |
| `vtuWriter.*` | Write ASCII or appended raw binary VTU files |
| `vtuOutput.*` | Assemble default and optional fields for spheres, LS particles, SPH particles, contacts, and bonds |
| `datWriter.*` | Write column-oriented DAT files |
| `energyOutput.*` | Aggregate solid-particle and interaction energy and write `energy.dat`; SPH-fluid energy is excluded |
| `myLSObject.*` | Provide `LSInfo` and common level-set input objects |

## Key Rules

- `copyHostToDevice*()` resizes the device storage to `hostSize()` and copies every `DeviceLayout` field.
- `copyDeviceToHost*()` resizes the host storage to `deviceSize()`; after completion, `hostSize()` is the valid device length.
- Single-field copies require equal host and device lengths.
- `setUseDevice(true)` records that device storage participates in computation but does not allocate or copy data.
- Host members omitted from `DeviceLayout`, such as material/geometry references and particle copies used by contacts, remain host-only.
- VTU output is binary by default; data generated by `myLSObject` is ultimately passed to `LSGeometryContainer`.

The container index of a `containerObject` is bound when the object enters `hostAoSDeviceSoA::host()`. Copying the object does not copy ownership, which prevents a user object from being reused in the wrong container.

## Extension Guide

1. Add the real member to the host class.
2. Add a unique field-tag type.
3. Add `deviceField<tag, &Class::member>` to `DeviceLayout`.
4. If kernels need grouped access, create a lightweight device view in the corresponding `.cuh` file.
5. Add a host→device→host round-trip test, including the host size after device-side modification.

## Container Architecture

```text
host_container_type = std::vector<T>
          |
          | copy fields declared by T::DeviceLayout
          v
device storage = one allocation per field + active deviceSize
```

`deviceField<Tag, &T::member>` binds a public field tag to the real host member. `deviceLayout<...>` lists the fields that participate in CUDA computation. `concatDeviceLayoutsT` lets a derived particle reuse base fields without duplicating declarations. Device views group raw field pointers for kernels but never own memory.

### Size and Capacity Semantics

| Operation | Host size | Device size | Capacity behavior |
| --- | --- | --- | --- |
| `resizeDevice(n)` | unchanged | becomes `n` | grows field allocations when required |
| `copyHostToDevice*()` | unchanged | becomes `hostSize()` | resizes device storage automatically |
| `copyDeviceToHost*()` | becomes `deviceSize()` | unchanged | resizes the host vector automatically |
| Single-field copy | unchanged | unchanged | requires equal active lengths |
| `resetDevice()` | unchanged | zero | releases or resets device storage according to the container implementation |

Asynchronous copies enqueue work on the supplied stream. The host buffer must remain valid until the stream is synchronized. Compound containers coordinate their member copies and synchronize only at an explicit public synchronous boundary.

### Ownership and Stable Indices

Types derived from `containerObject` remember the host container and index to which they belong. This metadata is intentionally absent from `DeviceLayout`. Solver insertion APIs use it to reject cross-solver materials, particles, contacts, and bonds. Public solver access is const because reordering would invalidate every stable reference into the host arrays.

## Output Pipeline

```text
solver-owned host state
    -> vtuOutput field selection and geometry expansion
    -> vtuWriter XML metadata + ASCII or appended binary arrays
    -> particle/ and interaction/ files

solid and interaction state
    -> energyOutput reduction
    -> datWriter columns
    -> energy.dat
```

`vtuWriter` is deliberately unaware of particles and contacts; it receives generic points, cells, and named arrays. `vtuOutput` performs domain-specific expansion, such as transforming LS surface nodes into world coordinates and separating movable from infinite-mass LS particles. Binary appended data is the default and uses explicit byte counts and offsets.

## Random Level-Set Particles

`levelset::makeRandomShape(radius, minimumSurfaceHeight, maximumSurfaceHeight, subdivisionLevel = 3, seed = 0)` in `myLSObject.h` returns an owned `TriangleMesh`. It applies a smooth, spatially correlated radial deformation to an icosphere, preserving a closed surface with outward normals. The result is star-shaped about the local origin: it can have lobes and indentations, but no holes or radial overhangs.

The height bounds are offsets from the base radius, in the same length units as that radius and the rest of the simulation. Sampled vertex radii span `[radius + minimumSurfaceHeight, radius + maximumSurfaceHeight]`; the planar faces interpolate those vertices. The base radius and deformed radii must be positive and finite, and the finite height bounds must be ordered. Equal bounds produce a spherical mesh. A fixed seed reproduces the sampled shape; subdivision controls mesh resolution.

The factory builds mesh-distance acceleration data, but does not allocate an LS grid. Build the grid separately at the desired simulation resolution before adding the geometry to a solver:

```cpp
#include "data/myLSObject.h"
#include "solver/LSDEM.h"

fundem::LSDEM simulation;
// All lengths here are metres: 10 mm base radius, offsets from -2 to +3 mm.
auto shape = fundem::levelset::makeRandomShape(0.010, -0.002, 0.003, 3, 42);
shape->buildLSGrid(40); // Target 40 cells across the largest bounding-box extent.
const int geometryIndex = simulation.addGeometry(*shape);
```

Signed distances are Euclidean distances to the generated triangle mesh, negative inside. They are not approximated by subtracting a directional radius.

## Adding Data Safely

When adding a new field, decide first whether it is dynamic device state, host-only configuration, or derived output. Device state belongs in `DeviceLayout`; host references and validation flags do not. Derived quantities such as kinetic energy are usually calculated during output rather than stored. Update device views and copy tests whenever a new device field is introduced.
